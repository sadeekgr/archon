Working design. Nothing here is final. Open questions are in this process's unknowns.

## Parts

| Part | What it is |
|---|---|
| State | The truth. The consequences of actions fall on it |
| Action | What can happen once chosen: performer, needs, uses up, applied to, and outcomes, each with its own probability |
| Agent | Its view (what it knows and expects, with its biases and limitations) and its choice (which action next, with what effort) |
| Event | A change nobody chooses: data going stale, a tool wearing, a shock, a technology arriving from outside |

## Kinds

| Kind | Rule |
|---|---|
| Agent | Chooses what it does |
| Resource | Used up when used; conserved when moved |
| Tool | Not used up; another copy is a replacement, with a cost |
| Information | Not used up; can be copied; can be wrong |

## Agent

- Anything that chooses what it does: a person, an AI, a machine or a robot.
- Separate from its role, so agents can be moved between roles and their performance compared.
- Attributes: knowledge, skill.
- Choice: for now, among the actions available to the agent, by probability. The full choice rule comes later.
- Term: "agent", not "person" (too narrow) or "actor".

## Knowledge and skill

- Attributes of the agent. Not resources, and not used up by use.
- Separate attributes. Neither implies the other in general.
- Where a skill cannot exist without certain knowledge, that knowledge can be assumed. Nothing else is assumed.
- Knowledge: information the agent has understood. Holding information is not knowing it.
- Skill can become obsolete, for example when the tool or the task changes.

## Resource

- Examples: coal, money.
- Used up when used. Conserved when moved: what leaves one place arrives in another.

## Tool

- Raises the output of the agent using it. Does not choose.
- Belongs to the role: an agent who leaves a role leaves its tools.
- Can be improved or replaced, and both are choices. Research by some agents can improve the tools that others use.
- The cost of a replacement varies by tool. Copying software is a replacement at a low cost; replacing infrastructure is a costly one.
- Buying a better tool raises output at once and costs money. Teaching an agent raises output over time. The two are modelled differently.

## Information

- Data: information about the current state of something. It goes stale as the state changes, and can be kept as a record.
- Other information lasts and can be learned from.
- Can be stored outside agents.
- Becomes knowledge only through an action, which takes time and depends on what the agent already knows.

## Source

- A source of something: what an action extracts something from.
- Resource source: holds resources. Example: a coal deposit.
- Information source: holds information of any kind. Examples: a paper, a manual, a report.
- Both kinds are much alike: something is put in, including actions, and something comes out.
- Sources can be produced by actions. The producer then knows the content well.

## Action

- On a resource: direct.
- On an agent: a request is sent, and the receiver chooses what to do.
- On a tool: it is instructed. That can take time, like a message, but the tool has no choice.
- Outcomes can produce, improve, degrade or destroy: a resource, a tool, information, knowledge, a skill.
- Takes time. Time is an attribute of many elements.
- Outcomes can depend on chance, so structures are compared over many runs. The chance must be repeatable. The conditions an organisation is run under are held identical across the structures compared; the chance of each action is not, by design, and many runs and the size of the organisation average it out.

## Observation

- Measure: a quantity the observers compute for any run.
- Criterion: the level or condition the observers judge by. The organisation need not know it.
- Aim: what the organisation or an agent strives towards. It belongs to them.
- Performance depends on the criterion. The design must allow many kinds of criterion and aim, alone or together, as set out in this process's constraints.
